# AELYXORA — First Compiler Front-End: COMP-01..05 Closure Candidate

**Status: PROPOSED / Phase I; no implementation or architect acceptance.** This document is a detailed engineering handoff for the **single** [first compiler contract](aui-compiler-first-implementation-contract.md), not a second grammar, compiler generation or competing Project Graph. It refines only P00–P06 source-only work, and preserves the [strict D3 L0/L1 language owner](d3-first-language-profile.md). Linked P07 and native P08–P10 remain outside the first executable frontend. The explicit decision table at the end is a proposal requiring human sign-off, not a list of claimed approvals.

## FC1. Proposed first host and Assembly module graph (COMP-01)

- **Host:** Windows 11 x64 user-mode as the first **candidate**, using ordinary Win64 calling convention for external boundaries and an internal Assembly program. Target of P00–P06 is **not** a user executable compiled from AUI: the compiler itself is a Windows PE CLI, and its AUI output is a non-executable typed-plan JSON. No Windows target triple is inferred from a source-only file.
- **Assembler/linker:** approved Clang integrated assembler / `lld-link` or the equivalent verified Windows COFF toolchain; all exact executable paths, versions, flags, SDK libraries, imports and tool hashes must be recorded before implementation. No Python, C++, Qt, Node.js, JIT, network resolver, handwritten executable file writer or unreviewed host-language bootstrap.
- **Process input:** a bounded, explicit command vector with modes `check` and `emit-plan`, `--source-only`, `--profile l0|l1`, `--core-catalog <path>`, one `<file.aui>`; only `emit-plan` may specify `--out <path>`. A duplicate option, unknown option, missing argument, NUL in path, wildcard, unsupported profile or extra positional argument rejects before opening an AUI source. Never launch a shell to interpret user arguments.
- **Host boundary:** Win32 wide-path I/O wrappers; each wrapper has a bounded UTF-16 input, exact handle ownership and a closed status classification. Use explicit no-follow/reparse-point and file identity policies for linked snapshots later; a source-only inspection can read an ordinary specified file but cannot follow a path into unapproved remote dependency resolution or execute source code. Output is staged in the caller-selected directory with exclusive creation, complete-write checks, close/verify and atomic same-volume publication; failures preserve existing good output. The exact NTFS atomic/flush durability guarantee belongs to D6 and is *not* claimed here.
- **Process compilation:** one input file at a time, no threads, callbacks, async parsing, runtime UI or automatic caching in the first CLI. All diagnostics are deterministic for fixed file bytes, frozen catalogue and compiler Unicode/grammar tables; host-local filesystem error messages may be additional human text, never part of canonical diagnostic code.
- **Module boundaries, in source order:** `cli` → `source_capture` → `utf8` → `lexer` → `parser` → `symbols` → `types` → `views_events` → `hir` → `plan_writer` → `diagnostics`. A `host_win64` leaf performs file I/O, allocations, and process exit; none of the compiler passes may invoke OS calls directly. No pass writes to user-controlled output before all previous gates succeed.
- **Lifecycle/ownership:** a single `CompilationContext` owns original source bytes, immutable token/trivia arrays, CST/AST/HIR arenas, string value pool, symbol table, diagnostics and optional staged output. Every pointer is a bounded view into context-owned storage, never an on-disk project ID. Exactly one release path destroys the context after success, diagnostic failure or controlled allocation failure. No pointer to a temporary compiler arena becomes a public source-only plan field. Error paths cannot continue into code generation.

The existing Linux x86-64 [JSON delimiter preflight](../../src/bootstrap/linux-x86_64/README.md) is experimental research, not a Windows port or an AUI compiler frontend. Do not make that preflight an unqualified dependency of the first Windows compiler.

## FC2. Unicode and lexical rules — precise candidate (COMP-02)

**Proposed pinned data version:** Unicode **15.1.0**, [versioned UAX #31](https://www.unicode.org/reports/tr31/tr31-39.html) XID properties and UAX #15 NFC, with explicit immutable source data and offline conformance tests. Source data comes from the [versioned Unicode UCD archive](https://www.unicode.org/Public/15.1.0/) rather than the mutable `UCD/latest` endpoint. The chosen older stable version is intentional; the host OS default or latest installed ICU/CRT version must **not** change compilation behavior. Before sign-off, confirm local permission to include only the required Unicode tables and record the **actual retrieved file SHA-256 values** in a checked-in dependency manifest; do not invent them. Required offline sources: `DerivedCoreProperties.txt` for `XID_Start` / `XID_Continue`, `UnicodeData.txt` and normalization composition/exclusion inputs, `NormalizationTest.txt` for NFC vectors. Table generation must use an explicitly approved native/Assembly build step or reviewed deterministic checked-in tables, **never Python**. These exact table bytes are part of compiler-input identity.

**Lexical state machine:** `Normal`, `LineComment`, `Identifier`, `UnsignedInteger`, `QuotedString`, `Escape`, `UnicodeEscape` and `StringSurrogatePending`. All transitions consume complete valid UTF-8 scalar sequences or ASCII bytes. Raw input bytes are hashed **before** normalization/decoding. UTF-8 rejects BOM, invalid leading/continuation bytes, overlong encodings, surrogate code points, >U+10FFFF and embedded non-ASCII spacing not explicitly admitted as source trivia. The only insignificant whitespace in first profile is ASCII SP/HT/LF/CR; CRLF is two original bytes but one logical line break for display. `//` comments consume through LF or EOF and preserve original spans. `/*` must fail as unsupported profile construct, never as division operator because division is not in L0/L1.

**Identifier rule:** first scalar must be in pinned `XID_Start` and later scalars in `XID_Continue`; ASCII underscore is not a permitted first scalar under this strict candidate if absent from XID_Start. Compare symbols by pinned **NFC normalized scalar sequence** (not locale-sensitive case-folding); preserve exact raw spelling and `[startByte,endByte)` to diagnose two distinct spellings that normalize identically. Case-sensitive ASCII keywords are checked on the decoded identifier, not on bytes inside strings. Contextual `io-worker` / `state-write` are sequences of `ID`, `-`, `ID` in a declared domain/effect position, not general minus arithmetic.
 
**String rule:** delimiting ASCII `"`, JSON-style backslash escapes only (`"\\/bfnrt` and `uXXXX` with valid surrogate pairing), reject raw C0 controls, invalid `\\u` hex or lone high/low surrogate. Raw valid UTF-8 non-ASCII scalars are preserved in decoded String and are never NFC-normalized: **only identifiers** are normalized for resolution. A string's decoded bytes have a separate bounded length; no implicit C terminator.
 
**Integer rule:** exactly `0` or `[1-9][0-9]*`. A decimal token with leading zero, sign, fraction, exponent or separator is an error, not split into two accepted tokens. Reject numeric overflow while scanning with checked arithmetic; integer literal >2^53-1 is `AUI_NUMBER_RANGE`, and a valid smaller decimal literal used as `U32` with value >4294967295 is `AUI_NUMBER_RANGE` in type checking. No negative number, floating point, unit literal or `F64` literal exists in L0/L1.
 
**Feature detection:** classify recognized `state`, `derived`, `bind`, `task`, `await`, `service`, `ForEach`, and import `@` version suffix in an otherwise recognized relevant construction as `AUI_PROFILE_UNSUPPORTED`. An unrelated user text string or ordinary identifier containing these substrings remains ordinary text/ID. Malformed UTF-8 always outranks profile diagnostics; a source may contain multiple diagnostics only after a known-good lexical stage. A future-feature token used outside an identifiable construction falls back to normal grammar diagnostics, not arbitrary privileged interpretation.

**Bounds (review candidates, never measured):** source <=1,048,576 bytes; tokens <=131072, imports <=64, top-level local declarations <=512, static views <=4096, nesting <=64, identifier UTF-8 spelling <=256 bytes, decoded string <=1,048,576 bytes, diagnostics <=100; entire `CompilationContext` live allocations budget <=64 MiB. A resource rejection occurs before the counter/allocator can overflow. Include actual context memory accounting and fail-safe allocator results. If output or diagnostic JSON exceeds the budget, return a controlled resource failure, never truncate a successful plan. The values are proposed and need COMP-02/D5 acceptance.

## FC3. Source-only type/effect and local UI checks (COMP-03 / COMP-05)

The [review catalogue](../../examples/aui-compiler-first-slice/review-type-catalog.json) is a **design-only exact name→logical type mapping**, not a signed core registry. Source-only resolution is confined to the explicit `import aui.core;` and optional `import example.locked;` aliases. Duplicate imports, unknown names, multiple matching aliases or unpinned external exports reject. For L1, declared imported nominal `Tick` and `Failure` are merely provisional types; exact current CoreTypeRegistry/OperationID/export digests are unavailable, and no linked or runnable output is permitted.

**Static properties:** `VStack/HStack` require exactly one `spacing: U32` argument and >=1 children. `Text` requires exactly one `value: String`, no children. `Button` requires exactly one `title: String`, no children; **exactly one explicit `.accessibilityLabel(value: String)` modifier is mandatory** even if `title` is nonempty. Each `accessibilityLabel` may occur at most once on a single View. A literal label must be nonempty; a bound input String label is typed but runtime nonempty validation remains a D5 obligation. Modifiers are ordered in the source and applied left-to-right. No extra property labels or implicit conversions. Unknown constructor/modifier/property => stable diagnostic, not a silently ignored visual.
 
**Event/command:** only Button may use exactly one `.on(activated: <declaredLocalEvent>)` per Button. That attachment has `Event<Unit>` payload, requires exactly one `on localEvent(payload) { send DeclaredCommand(namedArgs...); }` handler in L1 and no duplicate handler/attachment. Event without handler or command send to unknown provider is a source/linked diagnostic respectively; local valid command request does not imply a verified Graph provider. Handler payload local is immutable and only scoped to handler; all request arguments must resolve to type-equal imported inputs or handler-local values (no FFI pointer borrowing). No runtime queue, async delivery or hardware permission is inferred during static type checking.

**Effects:** `effects(...)` omitted means empty explicit set. Deduplicate after validating no repeated effect atom; declared effects/domain names are resolved against a **closed compiler review list** in source-only mode. Candidate accepted L0/L1 source-only **declared domains**: `io-worker` and `ui` are both syntactically/type valid as contextual atoms, but this recognition grants no runtime permission. A command declared `on ui` that is incompatible with a verified blocking provider is rejected at **P07 graph-link/target review**; source-only P05 cannot infer an external provider's blocking behavior. This preserves the existing [domain-mismatch negative case](../../examples/aui-language/d3-first-profile-negative-cases.json), whose expected stage is graph-link. Candidate accepted command effects: empty set; a textual `state-write` or hardware effect is not automatically authorized by syntax and must be rejected in L0/L1 source-only unless the exact trusted contract explicitly admits it later. Provider capability check happens only in P07/P08.
 
**Accessibility:** required explicit Button label is only a *static authoring validation*. It does not constitute keyboard interaction, screen-reader behavior, focus traversal, locale shaping or verified accessibility on Windows. Those remain D5 runtime tests.

## FC4. Internal compiler data shapes and deterministic source-only plan (COMP-04)

Each pass owns immutable output within the `CompilationContext`, never mutates a prior pass's original byte spans. An input or reference node is always indexed by **checked integer offset into its owning arena**, not a raw unbounded pointer or a persistent GraphNodeID. The actual *private* in-memory offsets/layout are an implementation detail within Assembly, but these **logical records and relationships** are required:

| Stage | Required record contract | Proof |
| --- | --- | --- |
| Source | `SourceUnit{originalBytes,originalLength,sourceSha256,path,profile,unicodeDataIdentity,catalogIdentity}` | Exact bytes never silently re-decoded from a normalized copy |
| Lex | `Token{kind,startByte,endByte,decodedValueRef?,normalizedIdentifierRef?}`; trivia adjacent to exact spans | No overlap, monotone boundaries, EOF consumes full source |
| CST | `SyntaxNode{kind,childrenInSourceOrder,tokenRange,sourceSpan,recovered}` | Error-recovered nodes never become successful AST |
| AST | `Module,Component,Input,Event,Command,Handler,View,Arg,Modifier` | IDs compiler-local, all links resolve, explicit source span |
| Symbols | `Symbol{namespace,normalizedName,sourceSpellingSpan,declNode,logicalType}` | NFC collisions/ambiguous imported names rejected |
| TypedHIR | As in [first compiler F4](aui-compiler-first-implementation-contract.md) | No unresolved types, no effects beyond profile, GraphOrigin absent |
| Plan | [Strict document schema](../../schemas/aui-compiler-source-only-plan.schema.json) | JSON status always `UNVERIFIED_SOURCE_ONLY`; no Graph approvals |

**Static View order:** source preorder: root local ID `v0`; children left-to-right `v1`, `v2` and onward. Preserve input and command argument declaration order, modifier order, View child order and original byte spans. Imports/effects are validated as unique sets then sorted lexically where serialized. A modifier argument references the span of its exact original expression; the View span covers constructor and its chained modifiers. A named argument `valueKind` and `typeId` are explicit. `GraphOrigin` is absent in a source-only plan, never `null`, dummy, guessed or derived from the component name.

**Plan schema completeness:** The [existing expected StatusPanel plan](../../examples/aui-compiler-first-slice/status-panel-l0.source-only-plan.expected.json) is a manually authored **design vector** corresponding to the unchanged 296-byte source and SHA `aaccb407277bd686fa561c2eecbb539a97a626112b6727d7f9c1a7597ce5b1e5`. Exact source hash was independently checked against those bytes, but **this is not a compiler run**. Every declared span must lie within the actual source and each parent View must contain child View spans. No successful plan may contain diagnostics, link/approval/native fields or unresolved AST placeholders. A failed check emits a *separate diagnostics report* rather than a success-shaped plan with errors.

**Canonical emission candidate:** deterministic D6-style JSON key sorting by UTF-8 bytes, no whitespace, lowercase JSON escapes as specified by D6; arrays obey semantic order (Views/commands/args/modifiers) or sorted identity (unique imports/effects). Include one trailing LF only if approved as a tooling convention, and keep that choice in the output-format identity. Never compute `semanticGraphDigest` over a source-only plan. Future compiled tooling must record exact unicode-table SHA, core catalogue byte SHA, compiler build ID and source SHA in its *evidence report*; input format hash does not prove public type exports.

## FC5. Diagnostics, rejection priority and fail-safe publication (COMP-02..05)

All compiler failures use one stable set of **source-oriented diagnostic codes** where defined by D3. `AUI_SYNTAX`, `AUI_PROFILE_UNSUPPORTED`, `AUI_UNRESOLVED_IMPORT`, `AUI_DUPLICATE_SYMBOL`, `AUI_ARG_DUPLICATE`, `AUI_TYPE_MISMATCH`, `AUI_EVENT_TYPE`, `AUI_EVENT_HANDLER_DUPLICATE`, `AUI_ACCESSIBILITY_LABEL`, `AUI_NUMBER_RANGE` and `AUI_COMMAND_CONTRACT` are review candidates with source-specific spans. The exact code set and stage precedence must be frozen in the [first compiler F6](aui-compiler-first-implementation-contract.md); no English runtime message is a stable machine-readable identifier.

A parser may synchronize at semicolon/brace **only for diagnostics**, marking every recovered node invalid. It must never output successful TypedHIR or emit a plan from a recovered subtree. Order diagnostics by **pass priority → original byte start → declared code tie-break**; cap count at 100 then emit one deterministic `AUI_DIAGNOSTIC_LIMIT` marker before terminating. Invalid UTF-8 or allocation failures may short-circuit earlier stages. Do not return "source-only PASS" for an unknown import, untyped Button modifier or an attempted future `Task` construct.

On failure, the OS exit code is nonzero and the *optional* human-readable error report contains exact source SHA, code, stage and half-open byte spans. It must not contain untrusted source excerpts that can execute as console escape sequences or inadvertently log secrets. A previously published `--out` artifact is not overwritten. No auto-fix, source rewriting, dependency download, native assembly, command dispatch or process execution is performed by source-only mode.

## FC6. Design evidence, dependencies and acceptance decision table

- [Compiler acceptance designs](../../examples/aui-compiler-first-slice/acceptance-cases.json) are NOT-RUN until an actual compiler exists. [Additional Unicode/diagnostic microcases](../../examples/aui-compiler-first-slice/unicode-and-diagnostics-cases.json) give exact UTF-8 hex/Unicode string/identifier/syntax expectations as *future* native parser tests.
- The first compiler must be verified with a real Windows x64 toolchain build, observed source-only `check` and `emit-plan` output, deterministic bytes, memory-budget and hostile-input tests. Cross-host normalization equality must be tested from pinned tables, not claimed from the developer's local Windows `NormalizeString` implementation.
- No Graph source link, native runtime, signable module, GUI preview, provider command or OS permission is accepted from a source-only output.
