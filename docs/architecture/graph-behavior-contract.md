# D2 — Graph Behavior: Workflows and Data Flows

**Status: proposed for explicit architect review. Not implemented, accepted, or tested.** This is the owning D2 behavioral specification. [D2 Execution and Consistency](d2-execution-consistency.md) owns the first-profile ordering, dispatch, cancellation/terminal linearization, ownership transfer and model transaction boundaries. [Project Graph](project-graph.md) owns identities and graph topology; [Project Format](project-and-package-format.md) owns encoding; [Graph Validation](graph-validation-and-migration.md) owns diagnostics and migrations; [AUI](aui-event-binding-semantics.md), [Runtime](aui-runtime.md), and [Component ABI](aui-component-binary-abi.md) own source and native execution semantics.

## B0. Non-negotiable invariants

1. One canonical semantic Project Graph owns stable component, port, edge, workflow, and data-flow identities. Maps, timeline diagrams, AUI previews, and traces are projections referencing those IDs; none can secretly establish another authoritative graph.
2. A workflow is an **explicit typed state-machine contract**, not code generated by following diagram lines. A transition cannot grant permission to call a device or system API.
3. A data flow is a **typed transfer policy over existing graph data-flow edges**, not an inferred connection. Capacity, ownership, ordering, failure and scheduling policies are part of the semantic model.
4. Durable graph revision, runtime state revision, workflow ExecutionID and AUI ViewIdentity are distinct; runtime observations never modify the architecture except through a separately reviewed graph transaction.
5. AI produces proposals for architecture/source changes but does not approve or execute them. Design fixtures describe expected behavior; their test result remains **not-run** until actual execution after implementation.

## B1. Stable identities

| Entity | Key | Rule |
| --- | --- | --- |
| Project | ProjectID | Stable across revisions/migration |
| Node | GraphNodeID | Independent of displayed label, source span and coordinates |
| Port | GraphNodeID / PortID | PortID unique within node; resolved against exact package export |
| Edge | EdgeID | Stable independent of file ordering and view layout |
| Workflow | WorkflowID | Unique project-level declaration |
| State | WorkflowID / StateID | Unique in workflow; not a graph node |
| Transition | WorkflowID / TransitionID | Unique and traceable in evidence |
| Running workflow | ExecutionID + definition revision | Ephemeral, cannot be confused with durable graph ID |
| Data flow | DataFlowID | Named group of canonical EdgeIDs |
| Binding | DataFlowID / EdgeID | One authoritative binding per active data-flow edge in initial scope |

**Proposed restricted portable graph IDs** use the regex [A-Za-z][A-Za-z0-9._-]*. Unicode normalization and collision policy remain an explicit D2 design decision, not something inferred from AUI source identifiers. Package TypeID remains package-qualified and resolved against a locked package content identity. All references are IDs, not text labels.

Validation resolution is ordered: schema -> targets -> locked exports -> nodes/ports -> edges -> binding definitions -> workflow states/transitions -> capabilities. Unknown references fail rather than being inferred.

## B2. Proposed edge taxonomy

| Kind | Allowed initial semantics | Implied execution? |
| --- | --- | --- |
| containment | Organizational parent-child; acyclic | No |
| hosts | **Physical topology** CPU -> bus or bus -> device for the initial sensor profile; acyclic and single-parent | No; never grants hardware access or OS privilege |
| dependency | Declared component/package dependency | Build/link ordering only |
| call | Typed call/command relationship, explicit provider and effect contract | Only after separately authorized dispatch |
| event | Typed occurrence source -> listener contract | Delivery only under declared runtime rules |
| data-flow | Output port -> input port, canonical exact TypeID or explicit pure adapter | Only under a DataFlow binding |
| interrupt | Declared IRQ source -> permitted handler | Requires target/platform capability |
| protocol | Declared compatible endpoint interfaces | No implicit I/O |
| resource-access | Component -> resource with exact scope/permission | No |
| ownership | Owner -> resource, exclusive unless shared policy | No implicit release |

The current sensor fixture uses 'hosts' for soc -> bus and bus -> sensor; this contract proposes that term **only for topology**, not deployment or execution ownership. It differs from 'containment' and must never be silently migrated to it. Unknown kinds cause GRAPH_EDGE_KIND_UNKNOWN. Portless topology edges are legal; data-flow edges require explicit valid ports. Nonstandard extension edges may be preserved as inert metadata only after a separately specified namespaced extension rule.

## B3. Data-flow semantic contract

A DataFlow declaration groups channel bindings by **existing EdgeID**. The endpoints cannot be copied into another editable model. Every active data-flow edge has exactly one binding in this first profile (FLOW_DUPLICATE_BINDING if duplicated). Missing or wrong-kind edges reject with GRAPH_MISSING_EDGE or FLOW_EDGE_KIND.

Every channel binding must specify:

- edgeId; mode **stream** or **snapshot**; senderDomain and receiverDomain; transfer **copy**, **move**, or **borrow**; ordering; errorPolicy.
- A **stream** additionally specifies capacity > 0, bounded by the target budget, overflow **reject**, **drop-newest**, **drop-oldest**, or **block**, and FIFO order for accepted messages from one producer.
- A **snapshot** has one authoritative writer, no queue capacity/overflow field, and the latest **committed** value. Snapshot ordering is 'latest'.
- Error policies are 'propagate', 'reject-and-report' or 'drop-and-report'. Every intentional drop is observable. Block is illegal in IRQ, UI, and other declared nonblocking execution domains.
- No at-least-once or exactly-once delivery guarantee is inferred from the drawing. Durable replay/acknowledgement requires a future explicit contract.

**Ownership:** copy keeps original ownership; move transfers only when accepted under the native ABI, retaining sender ownership on rejection; borrow is restricted to bounded synchronous same-domain use and cannot cross scheduler domains, await, thread queues or process/device boundaries. Cross-domain borrow -> FLOW_CROSS_DOMAIN_BORROW. Transfers between address spaces additionally require serialization and adapters.

**Type and writer rules:** matching canonical exported TypeIDs, unit and port direction, exact target compatibility, explicit pure adapters for conversions, declared fan-in and error paths. Two writers to an exclusive input -> FLOW_WRITER_CONFLICT. An immediate binding cycle without explicit state/delay -> FLOW_COMBINATIONAL_CYCLE. A runtime stream cycle is not automatically forbidden, but requires capacity, scheduling and backpressure proof; an async edge alone does not certify deadlock freedom.

**Sensor proposed example:** e3 is driver.sample (example.sensor/RawSample) -> decoder.raw: stream, capacity 32, overflow reject, FIFO, copy, io-worker to io-worker. e4 is decoder.reading (example.sensor/Measurement) -> app.reading: snapshot, latest, copy, io-worker to ui. Queue-full rejection must be reported; no fabricated valid Measurement on decoder failure. This is a specification only: the sample ASM package sources do not exist.

## B4. Workflow semantic contract

A workflow has a stable id, ownerNodeId, trigger, exactly one initialState, a nonempty set of unique states, a declared signal list, bounded admission policy and transitions with unique IDs. Terminal states are explicitly typed success/failure/cancelled and have no outgoing transitions. Every transition has from, to, a signal name, and an action. For initial D2 profile:

- Trigger is 'data-arrival' bound to a canonical data-flow EdgeID with an existing binding. A later 'event' trigger must resolve an exported Event TypeID and is not yet covered by the schema fixture.
- Action is 'none', 'dispatch' to a known component provider operation, or 'publish' via a bound data-flow edge. A graph connection by itself cannot launch a command or privileged I/O.
- A workflow runtime instance starts from initialState with its own ExecutionID and frozen architecture revision. A triggering data-flow event creates a new instance only after bounded admission; signals for an existing instance are serialized by its per-instance FIFO mailbox. No global cross-instance ordering exists. See D2 Execution and Consistency.
- Duplicate transitions with the same from+signal require an explicit ordered/guarded policy; unsupported ambiguous transition -> WORKFLOW_NONDETERMINISTIC.
- Terminal states cannot have outgoing edges; unreachable states are invalid (WORKFLOW_UNREACHABLE_STATE). A transition to an unknown state -> WORKFLOW_STATE_UNKNOWN.
- A missing dispatch component -> WORKFLOW_NODE_UNKNOWN. A component without the exact exported command implementation -> WORKFLOW_PROVIDER_UNRESOLVED. A publish transition not originating from the action component's output / bound edge -> WORKFLOW_PUBLISH_INVALID.
- The **proposed first-profile policy** is per-instance-fifo with explicit maxConcurrentInstances, mailboxCapacity and reject-and-report overflow, no automatic retry, typed signals, and one terminal publication. See [D2 Execution and Consistency](d2-execution-consistency.md). Machine-level atomic ordering, device safety and scheduler implementation still require D4/D5 proof; cancellation is a request and never guaranteed physical abortion.

**Sensor reference workflow:** sample-to-measurement owned by decoder, triggered by arrival on e3. Signals are: sample-arrived (RawSample), decoded (Decode success: Measurement), decode-error (Decode failure: DecodeError), cancel and cancel-confirmed (runtime control). States are waiting (initial), decoding, cancelling, done (success terminal), failed (failure terminal), cancelled (cancelled terminal). Waiting + sample-arrived dispatches Decode and enters decoding. Decoding + cancel enters **nonterminal** cancelling and requests cooperative cancellation without freeing a live device/command buffer. Cancelling + cancel-confirmed publishes cancelled; cancelling + decoded publishes the actual success to e4; cancelling + decode-error publishes failure. Waiting + cancel may go directly to cancelled before any ticket exists. Only the first terminal outcome wins; competing late completions are diagnostics. The reference remains a design fixture without linked Assembly code or tested native runtime.

**Execution boundary:** semantic graph updates, in-memory workflow transitions and external hardware/network effects are three separate transaction domains. They must not be misrepresented as a single atomic operation. Exact scheduling/ownership and project CAS semantics are specified in [D2 Execution and Consistency](d2-execution-consistency.md); byte-durable journal and ABI semantics remain D6/D4 obligations.

## B5. Deterministic diagnostics and failure semantics

| Invalid candidate | Expected first diagnostic |
| --- | --- |
| Noncanonical unknown edge kind | GRAPH_EDGE_KIND_UNKNOWN |
| Missing referenced binding EdgeID | GRAPH_MISSING_EDGE |
| Topology 'hosts' used as transport | FLOW_EDGE_KIND |
| Stream capacity 0 | SCHEMA_INVALID (structural layer first; FLOW_CAPACITY_INVALID only if bypassed) |
| Borrow from worker to UI | FLOW_CROSS_DOMAIN_BORROW |
| Duplicate exclusive writer | FLOW_WRITER_CONFLICT |
| Transition destination unknown | WORKFLOW_STATE_UNKNOWN |
| Workflow triggered from topology edge | WORKFLOW_TRIGGER_KIND |
| Dispatch node absent | WORKFLOW_NODE_UNKNOWN |
| Provider operation missing | WORKFLOW_PROVIDER_UNRESOLVED |
| Synchronous binding cycle | FLOW_COMBINATIONAL_CYCLE |
| Unauthorized effect | CAPABILITY_DENIED |

Schema failures take precedence over semantic errors, then identities and references, then edge compatibility, binding policies, workflow semantics, capabilities; within a category diagnostics sort deterministically by stable ID and location. Runtime queue-full, cancellation, deadline and decoding errors are **typed operational outcomes**, not schema errors. A rejected input/model transaction leaves previous committed project bytes unchanged.

## B6. Model transactions and revision rules

Every change to node/port/edge, workflow/transition, data-flow policy, target, capacity or capability requires an expectedRevision-checked semantic transaction. A UI-only map movement is view state and cannot change semantic digest or rebuild inputs. Delete of an edge still referenced by a workflow or data-flow without a simultaneous valid fix -> GRAPH_REFERENCED_EDGE. Source changes affecting contracts are reconciled through a staged graph diff and human review, with source ownership protection. Undo/redo validates revisions; it cannot undo physical side effects.

Migration must preserve stable IDs and exact semantic meaning or declare an incompatible change; 'hosts' must not turn silently into 'containment'. ABI-relevant changes invalidate dependent build artifacts and leave prior evidence linked only to old digests. Byte-level hash and crash journal semantics remain owned by D6 and are **not frozen here**.
